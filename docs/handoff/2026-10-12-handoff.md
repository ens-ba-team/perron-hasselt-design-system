## 1. What this project is

A **back-office prototype** for Perron Hasselt, a student housing operator in Belgium. It manages rooms, tenants, bookings and maintenance.

- The real product is **WordPress + ACF Pro + Admin Columns Pro**, target: **no custom code**.
- This repo holds a **React prototype** (Next.js) that the WordPress developer will *look at* and rebuild. So the prototype must only show things WordPress can actually do.
- It also holds the **design system** (fork of Agentic DS), re-themed navy/gold for Perron.

### The two rules that override everything

1. **BR01 / R0 — nothing is automatic.** The system never changes a value the admin typed. No cron, no status that flips on a date, no automatic emails. Only store, filter, display. The client calls it *"an extended version of Excel"*; the operators are older and distrust magic.
2. **BR03 / R24 — money follows the contract.** `Available from` and the contract total come from `contract_start` / `contract_end`, never from the check-out date. A tenant who leaves early still pays.

If a request seems to break these, say so before building it.

## 5. What the prototype does today

Four modules: **Rooms, Bookings, Tenants, Maintenance**. Each has a list and a record drawer.

| Area | Behaviour |
|---|---|
| Lists | Read-only. 64px rows, zebra, sticky header, sticky ID column (with sideways shadow), Actions column (Edit / View) revealed on hover. Pagination 10 / 20 / 50, default 10 |
| Opening a record | The **ID** in the first column, or the Edit / View action. Opens a **Sheet, `size="wide"` (560px)** over the list. URL carries it: `?record=RM-1027`, `?record=new` |
| Record IDs | `RM-` rooms, `TN-` tenants, `PH-` bookings, `MT-` maintenance. **Mock values only** — in WordPress the dev uses post IDs |
| Bookings tabs | All · Upcoming · Active · Ended · Cancelled · **My task** (due this week, assigned to me) · **This week** (due this week, anyone) |
| Overlap check | Creating a booking: enter contract dates first, rooms already booked are **marked and sorted last**, never hidden |
| Dates | `DateField` (DS DatePicker), stored ISO, shown `MMM d, yyyy` |
| Photos | Check-in / check-out inspection photos are **uploads**. Contracts and IDs stay a Drive link |
| Mock data | "Today" frozen at **2026-10-08**. Hard cases listed in `_shared/scenarios.ts` (`HARD_CASES`) |

### Decisions that are settled — do not re-open without asking
Numbered in `CHANGELOG.md`. The ones most likely to be second-guessed:

1. **Record drawer, not a separate page.** A per-record edit page (closer to the WordPress edit screen) was considered and **parked**, not rejected.
2. **Sheet, not Drawer.** Sheet = desktop side panel; Drawer = mobile bottom panel. The 560px variant lives on **Sheet** (`Side=Horizontal, Size=560px`, node `2070:6175`).
3. **No inline editing.** One editing surface: the drawer. See the warning in §6.
4. **Secondary gold is final** even though hover contrast fails (2.2:1). Never suggest changing it.
5. **Dark mode is out of scope.** Do not audit or sync Dark tokens.
6. Related records inside a drawer collapse; a record's own fields never do.

## 7. Traps that cost the previous agent time

| Symptom | Cause | Fix |
|---|---|---|
| Prototype renders in **Times**, fonts look wrong | Stale Next build cache keeping old CSS | `rm -rf agentic-ui/.next`, restart. Check `getComputedStyle(document.body).fontFamily`, not the CSS variable |
| Storybook shows a different font than the app | Storybook loads fonts separately | `agentic-ui/.storybook/preview-head.html` |
| Page looks broken / empty in the Browser pane, `getBoundingClientRect` returns 0 | React 19 reveals streamed content with `requestAnimationFrame`, which pauses while the pane is hidden | Front the tab or take a screenshot first, then measure |
| Sticky table header does nothing | The DS `Table` wraps itself in its own `overflow-auto` div; sticky positions against that | Pass `wrapperClassName="h-full"` and give the parent a bounded height |
| `ComboboxField` shows the raw value instead of the label | DS bug, not fixed | Prototype works around it in `bookings/_components/booking-drawer.tsx` |
| `AlertDialogAction` rejects `variant` | Its comment lies | Use `asChild` + `<Button variant="destructive">` |
| Dev server "running" but your changes are missing | Another session's server on port 3100 | `preview_stop` then `preview_start`, after clearing `.next` |
